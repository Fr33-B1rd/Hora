# Daylight · Personal AI Assistant Demo

把想做的事排进喜欢的一天，并在变化发生后重新协调。

独立于当前 Godot 项目的本地网页应用，无第三方运行依赖。重点演示「表达意图 → 比较方案 → 确认行程 → 会议冲突 → 保留承诺并重排」。界面为中文，适配桌面与窄屏。

## 启动

Windows 双击 `start-demo.bat` 在后台启动，再打开 <http://127.0.0.1:4318>。启动窗口关闭后服务继续运行；重复启动会复用已有服务。双击 `stop-demo.bat` 可停止该启动器管理的进程，保留已保存数据。停止入口会检查进程编号与启动时间，避免停止编号被复用的其他进程。

也可以在本目录运行：

```powershell
node --env-file-if-exists=.env server.mjs
```

需要 Node.js 24 或更新版本（使用内置 SQLite）。Windows 启动脚本优先使用 PATH 中的 Node，也兼容这台机器的 Codex 内置 Node。没有 `.env` 时会提示并继续运行本地演示，不需要密钥，不收费。服务只监听本机 `127.0.0.1`，不是公开部署。上面的手动前台启动方式可在终端按 Ctrl+C 停止。后台服务输出保存在 server.log 和 server-error.log；本版不设置开机自启，电脑重启后需再次运行启动入口。

## 斯德哥尔摩真实服务

默认入口及「规划行程」：<http://127.0.0.1:4318/#live>。使用 SEK 与 Europe/Stockholm。Nemotron 已真实验证；Google 地点、逐段公共交通、Calendar OAuth 与忙碌读取已真实验证；真实日历创建、重复确认不重复建事件、会议重排更新和锁定电影保留均已验收；每次日历写入仍须对具体方案预览确认。配置步骤见 [GOOGLE_SETUP.md](GOOGLE_SETUP.md)。

现在可直接走完：**一句话 → 三套真实地点建议 → 预览并确认 Google Calendar → 加入会议 → 保留锁定时间并重排**。

1. 输入 T-Central 出发、理发＋拉面＋电影、1000 SEK、13:00–20:00，点击「生成三套行程」。自动查询地点、常规营业时间与每段实际出发时刻的交通，读取主日历的忙碌时段。
2. 比较「紧凑顺路 / 口碑优先 / 从容一点」，选择后时间线与 Google Maps 链接同步更新。出发点默认采用 Google 首个匹配，可在规划偏好里更正。
3. 展开「把活动信息核实清楚」中的活动：填写已核实价格及来源，电影名称或服务项目、开始时间和时长；时间状态区分尚未核实、已查阅但未预订、用户已购票／预约成功。确认来源后应用并重排。未知价格留空，继续使用预算预留；已核实价格绑定当天该地点，已核实时段锁定时间和地点。应用失败时不会覆盖旧核实记录。
4. 检查状态后预览日历并最终确认。只有用户报告已购票／预约成功的活动移除「暂定」，其他活动仍显示暂定。日历包含状态、金额和核实时间，来源说明只保存在本机；提醒提前 10 分钟。
5. 可锁定电影个人时间，填写线上会议开始/结束，点击「加入会议并重排」。页面对比原方案或当前日历，保留锁定地点和时间；新会议和变动都需再次预览确认。
6. 重复确认不会重复建事件。刷新页面可恢复 15 分钟内的候选；服务重启后，未过期的写入预览仍可重试。过期后重新生成，已确认记录仍可查看。

公共交通查询没有路线时，会额外查询真实步行路线并明确显示；不会编造耗时。三种方案是有限候选搜索，不保证全局最优，条件紧张时可能少于三套。线上会议按可在当前地点参加处理；线下会议通勤未实现。Google 常规营业时间不保证特定日期营业或有空位。核实数据由用户查阅来源后录入，不自动抓取电影票或预约订单。新闻、商家预约、付款、参会邀请和后台监控仍未接入。

## 上海虚构场景：两分钟体验路线

1. 进入「上海演示」，使用示例需求：理发、拉面、电影，预算 200 元，公共交通，晚上 8 点前回家。
2. 比较「轻松一点 / 高效出行 / 精打细算」。预算、出发时间、返家时间、活动和出行方式均可编辑。点击地图标记或活动查看来源边界；「查看校验」展示约束检查。
3. 选择「就按这个安排」，预览后确认。保留默认勾选的「电影已购票」模拟状态，形成不可自动修改的承诺。
4. 「模拟新增会议」，使用默认 14:00–15:00。查看原安排与新安排，电影地点、开始时间保持不变；确认后更新本地日历。
5. 添加 17:15–17:45 的第二场会议，与已锁定电影直接冲突。助手明确说明需要移动会议或主动解除电影锁定，不伪造可行结果。
6. 查看「演示日历」，导出 `.ics`；在「偏好与记忆」查看操作记录，编辑预算、交通偏好或添加个人备注。
7. 「试用活动提醒」可在页面打开时触发 10 秒提醒；开启勿扰则暂缓。最后用「偏好与记忆 → 重置演示数据」恢复初始场景。

## 可选：接入 Nebius / NVIDIA Nemotron

复制 `.env.example` 为 `.env`，在本机填写自己的 `NEBIUS_API_KEY`，重启服务。密钥仅在服务端读取，不写入浏览器。不要提交 `.env`。

默认示例配置来自 [Nebius 官方 Nemotron 3 Super cookbook](https://github.com/nebius/token-factory-cookbook/blob/main/models/nemotron/nemotron3-super-120B.md)：

```dotenv
NEBIUS_API_KEY=your_key_here
NEBIUS_BASE_URL=https://api.tokenfactory.us-central1.nebius.com/v1
NEBIUS_MODEL=nvidia/nemotron-3-super-120b-a12b
```

`NEBIUS_BASE_URL` 与 `NEBIUS_MODEL` 均可配置。主对话由模型按需加载项目内 skills，选择工具、读取结果并决定下一步；程序负责工具权限、参数校验、排程及日历确认。发送内容包括当前输入、最近对话、规划条件和已查询的工具结果；不发送日历事件标题或私人描述。单次模型调用最多45秒，每轮最多24次模型请求、28次工具调用，整体预算180秒（已开始的外部请求可能延长至其超时）。最多同时处理两个模型请求会话。配置密钥不代表连接已验证。

2026-10-05 已实测 Nemotron 的约束工具调用；结构和数值经过程序校验。早期版本仅暴露 propose_constraints；当前主对话工具见下文，仍没有向模型开放日历写入权限。上海场景仍使用虚构数据，斯德哥尔摩页在缺少 Google 凭据时明确禁用真实地点查询，不静默回退。

- `server.mjs` / `lib/http.mjs`：本机服务入口、接口、短期方案与确认预览。
- `lib/journey.mjs` / `public/journey-ui.mjs`：斯德哥尔摩自动推荐、会议重排与确认流程。
- `lib/model.mjs`：真实 Nebius 意图解析和约束提议工具。
- `lib/maps.mjs` / `lib/live-planner.mjs` / `lib/time.mjs`：Google 数据、真实路线排程与 Stockholm 夏令时。
- `lib/calendar.mjs` / `lib/store.mjs`：OAuth、冲突检查、稳定事件编号、加密令牌与重试状态。
- `public/live.mjs`：斯德哥尔摩服务状态、真实地点选择和日历确认界面。
- `public/planner.mjs`：演示数据、排程、承诺校验、本地解析和日历导出。
- `public/app.mjs`：交互、确认流程、浏览器存储、提醒和页面。
- `public/style.css`：响应式界面；不依赖外部字体、地图或图片。
- `tests/`：排程边界、独立约束检查、日历导出与 HTTP 接口检查。

### 当前方案地图

斯德哥尔摩真实规划页（/#live）已加入 Google 地图，显示起终点、按行程顺序编号的活动地点及真实步行/公共交通路径。切换方案、应用核实或重排后同步更新；地图和时间线支持互相定位、查看全程及折叠。需要单独的 GOOGLE_MAPS_BROWSER_KEY，配置见 GOOGLE_SETUP.md。未配置或地图加载失败时保留时间线与导航链接。

### 语音对话

在斯德哥尔摩规划页点击「开始说话」，首次使用需在浏览器允许麦克风。说完点击「结束说话」，检查或修改转写，然后「发送」。支持中文、英语和瑞典语识别；回复以中文显示和朗读，可关闭自动朗读或随时停止。每轮最多 60 秒，切到后台或离开规划页会停止收音与朗读。

- 第一次可以说完整行程需求。后续说「预算改为 900 瑞典克朗」会携带当前日期、出发点、活动、预算和时间条件重新生成候选。
- 「选择第二个方案」直接切换现有方案并同步地图；「讲讲当前方案」按实际行程概述；「刷新日历并重排」重新查询日历与交通。未保存的活动核实编辑仍需先处理。
- 日历写入必须在页面检查预览并手动确认；语音不会代为购票、预约商家或发送邀请。新增会议仍使用现有会议表单。当前支持多轮需求讨论、行程工具与本地新闻活动查询；语音仍是录音结束后转写，再手动发送，不是实时双向通话。

识别已改为本机 faster-whisper small（CPU int8，4 线程），浏览器只通过 MediaRecorder 录音，不使用浏览器的云端 SpeechRecognition。点击结束后，音频送到本机 127.0.0.1 服务，在内存中转写，随后释放，不保存录音文件、不转发云端。中文识别结果经 OpenCC t2s 转为简体，英文与瑞典语保留原文。转写仍需检查后手动发送给行程助手。朗读沿用浏览器 SpeechSynthesis，优先本机中文声音。

首次在 Windows 运行 `./setup-voice.ps1` 安装独立 `.venv-voice` 和约 484 MB 的模型，再重启 Daylight；本机已安装完成。安装完成后，识别模型强制离线加载，不需要额外 Key。默认自动使用该目录；其他机器可配置 `VOICE_PYTHON` 与 `VOICE_MODEL_DIR`，`VOICE_DISABLED=1` 可禁用。依赖记录在 `voice-requirements.txt`，PyAV 固定为兼容版本 16.0.1。模型安装与运行不修改原 Anaconda 环境。

页面先检查本机模型能否加载，成功才开启录音按钮；连接失败、麦克风拒绝、无语音和转写失败分别提示。最长录音 60 秒，最大 4 MiB；转写一次一个请求，限时 120 秒。取消、离页或切到后台会停止收音并中止正在等待的转写；不会因失败自动上传其他服务。

接口依据：[faster-whisper](https://github.com/SYSTRAN/faster-whisper)、[MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder)、[SpeechSynthesis](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis)。


### Agent 与项目 skills（2026-10-07）

文字和录音后的转写共用 `/api/agent`。执行方式为：用户目标 → 模型加载相关 skill → 调用工具 → 读取工具结果 → 决定查询、调整、提问或结束。结束前由独立的模型检查请求与实际观察是否一致；发现遗漏则把具体问题返回同一执行循环，最多核对两次。检查器不能执行工具或授予权限，也不是语义正确性的形式证明。工具结果会返回同一个模型上下文；不再通过固定必填项追问和独立话术生成器推动主对话。

- `agent/AGENTS.md`：整个助手的行为、事实与权限边界。
- `agent/skills/plan-outing/SKILL.md`：通用本地活动、候选比较、失败后修订。
- `agent/skills/verify-activity/SKILL.md`：地点资料与实际可用性证据的核对边界。
- `agent/skills/local-discovery/SKILL.md`：本地新闻及附近活动，按需求选择来源。
- `agent/skills/calendar-review/SKILL.md`：读取忙碌时段、检查改动，并交给页面预览确认。

这些文件是应用实际加载的运行规则。启动一轮对话时只提供名称与简介；模型调用 `load_skill` 后才加载正文并启用其白名单工具。新增行为可修改 skill；新增外部能力仍需实现工具适配器及白名单，不能通过 Markdown 获得任意执行权限。详见 [架构说明](agent/ARCHITECTURE.md)。

搜索只收集地点，不会隐式改变起点或已选活动。模型另行选择观察到的地点编号，再调用确定性排程器。活动不限类别，一天最多6项；模型记录地点身份、先后顺序、预算和步行限制。未知费用默认暂按每项200 SEK预留，属于可调整估计，绝非真实报价。未定预算可先查询，明确不限则无硬金额上限。用户委托时间时由模型选择并记录暂定时段，没有统一的自动放宽窗口。模型仍可能漏解语义，规划可行不等于理解一定正确。

每轮最多12次地点搜索/详情查询、36次排程路线查询（公共交通无结果时适配器的步行回退可能增加实际 HTTP 请求）；配额不会在重新规划时重置。执行时间/调用上限、重复无进展调用和工具错误会明确反馈。页面回复可展开处理记录，只有动作、结果摘要与状态，不包含内部思考。暂定条件随当前标签页对话状态保存。

日历标题、描述、参与者和私人地点不传给模型；忙碌区间、已查询的公共地点、交通结果及候选概况会提供给模型。工具不能确认写入、付款、商家预约或邀请他人。真实日历仍需用户勾选并预览后手动确认。不可确定的旧活动位置衔接继续阻止保存。官网链接、地图营业时间不等于场次、余票、库存或参观权限已验证；活动核实表继续用于记录实际来源。

新闻来自 SVT Stockholm 最近72小时的 RSS 标题/摘要；活动来自 Visit Stockholm 精选页，主对话默认当天（兼容独立接口默认7天）、所述地标直线约3km内，结果不代表穷尽附近信息。来源失败会作为工具观察交还模型；可继续使用成功来源并解释限制。尚无任意网页全文读取、跨设备长期记忆或后台主动推送。

兼容性：折叠的完整需求表单仍使用 `/api/journey`；手动核实、会议重排和日历确认沿用已有确定性接口。旧 `/api/chat` 保留供兼容测试，主聊天不再调用它。没有把这些旧入口冒充新的自主执行循环。上海页仍是虚构数据演示。
